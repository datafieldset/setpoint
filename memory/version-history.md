# Version history (condensed)

Earlier history (v9-v14ish): initial build, pricing (`lib/pricing.js`), landing page, guide page, backtest report generation, whale-flow tracking, regime-aware verification concept introduced.

v15.x: Landing/guide copy rewrites (Morning Brew voice). Sub-view URL persistence fix. News feed removed (Reddit/Bluesky 403 confirmed). Market Meter moved to 5m, colored by real direction, scope note added. Live win rate threaded from the real gate.

v16.x: Regime-aware verification introduced properly — `getLiveVerifiedGate()` returns both overall and regime gates, `signal_track.regime` column added. Root-cause fix: live gate can only refresh/demote an already-statically-proven signal, never promote a statically-weak one on a lucky rolling window (found after a real, direct audit showed the blended, all-time track record at 44.5%, well below what "verified" should mean). 10 weak signals formally cut with dated, real evidence in `SIGNAL_RATES` comments. Coil and Swing added as testing signals.

v17.0-17.3: Swing (RSI-extreme + structural break) and Swing Early (fires at the turn, no confirmation wait) added. `computeSignals` refactored into 11+ separate detector functions. Testing-tier signals extended to persist correctly in open-positions/recently-resolved (were disappearing after their triggering bar passed).

v17.4-17.9: Push/logging decoupling bug found and fixed (client-side). Both crons' scheduling reliability fixed (2h trigger + internal 5-min loop, see infrastructure.md). Rolling live percentage surfaced on testing-signal cards. Whale Flow rebuilt to require a real oversold/overbought condition alongside the large trade (plain size alone had been cut). Real, live percentage display bugs found and fixed across `/api/open-positions` and the client's own, duplicated verification checks — consolidated onto `provenContext` directly.

v18.0-18.9: Regime-only verification extended so a combo can be "proven" with zero static promotion, purely from a strong, current, condition-specific record (≥10 trades, ≥58%). Signal catalog (`/api/signal-catalog` + `SignalCatalog` UI) built — full, honest census of all 15 signals. Public-stats (`Watch Live`) redesigned twice: first to only count each verified combo's own real, most-recent 20 trades (not all-time history); second, deeper fix to stop retroactively counting stale history the instant a combo became regime-verified. Momentum promoted (4h, against-bias gated) after it was found to have caught a real market move with zero data behind it, because it had never been promoted or added to testing — led to the standing "always log everything" principle. Full, direct, independent audit run across all 15 signals/6 timeframes against deep BTC history; several large-sample, conclusively-dead combos added to `KILLED_COMBOS`; Grind Up's stale static promotions retired after a deeper audit directly contradicted them. Swing|15m|bear and Volume spike|15m|bull promoted after directly deepening thin, promising samples across all 4 coins.

v19.0-19.2: Found and fixed the same regime-blindness bug (public-stats and signal-catalog both silently ignored regime-only verified signals entirely) — this was the deeper root cause behind "the dashboard shows real wins the public page doesn't reflect." Both names (internal + customer-facing brand) shown together in signal-catalog to prevent confusion. Cron push decision fixed to re-fetch fresh live/regime gate data right before sending, instead of reusing a snapshot from the start of a potentially long-running check.

v19.7: Whale Flow fully retired (both directions genuinely weak on deepened, cross-coin evidence) — see signal-roster.md.

v19.9: Neon compute-hour quota fully exhausted (real, live 402s from the database) — root cause confirmed directly from Neon's own usage numbers: two separate, overlapping cron workflows kept the database almost never idle. Combined into one workflow, trigger interval stretched from 2h to 5h to match real run duration, and the Sep 25 push-decision re-check fixed to use a short, real cache (90s) instead of fully bypassing it. See infrastructure.md's "Neon compute-hour incident" for the full, real numbers and reasoning.

## Numbering note
Version numbers are informal, bumped per real, deployed change, tracked in git commit messages (`vX.Y`) — not tied to a formal release process. Check `git log --oneline` for the authoritative, current sequence.
